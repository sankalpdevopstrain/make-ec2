## Setting Up AWS Credentials (Environment Variables)

To allow Terraform to interact with AWS, credentials must be configured using environment variables.
```bash
$env:AWS_ACCESS_KEY_ID="your_access_key"
$env:AWS_SECRET_ACCESS_KEY="your_secret_key"
$env:AWS_DEFAULT_REGION="eu-west-1"
```

1. Commented out each task I am going to do:
```bash
# Tf script for making an EC2 Instance on AWS
# Where to create this resource
# Which region to create it in
# terraform init - download required dependecies for that cloud service provider
# Which service?
# Which AMI?
# What instance type?
# Do we want a public IP address?
# Name of resources
```
2. Defined the provider (AWS)

Since the resource will be created on AWS, I added the provider block:
```bash
provider "aws" {}
```
3. Specified the region

I then defined the region inside the provider block:
```bash
provider "aws" {
  region = "eu-west-1"
}
```
4. Defined the EC2 resource

Next, I added the EC2 instance resource:
```bash
resource "aws_instance" "first_app_instance" {}
```
5. Configured the AMI

I specified the AMI using a variable for flexibility:
```bash
ami = var.app_ami_id
```
6. Selected the instance type
```bash
instance_type = "t3.micro"
```
7. Enabled public IP
```bash
associate_public_ip_address = true
```
8. Added tags for identification
```bash
tags = {
  Name = "tech601-sankalp-tf-instance"
}
```

## Core TF commands/workflow
### `terraform init` – Initialisation
Purpose: Prepares the working directory, downloads the required provider plugins.
```bash
terraform init
```


### `terraform fmt` – Format Configuration
Purpose: Ensures Terraform files are properly formatted and consistent.
```bash
terraform fmt
```



### `terraform plan` – Preview Changes
Purpose: Shows what changes Terraform will make before applying them.
```bash
terraform plan
```


### `terraform apply` – Apply Changes
Purpose: Creates or updates the infrastructure based on the plan.
bash
terraform apply
```
Terraform asks for confirmation (yes), then provisions the resources.




### `terraform destroy` – Destroy Resources
Purpose: Deletes all resources defined in the configuration.
```bash
terraform destroy
```
Terraform asks for confirmation (yes), then deletes the resources.

## Terraform `.gitignore`:
A .gitignore file for Terraform projects ensures that sensitive data, local state, and temporary files do not get committed to version control. This is critical for security and collaboration.

`gitignore`:
```bash
# Local .terraform directories
.terraform/

# .tfstate files
*.tfstate
*.tfstate.*

# Crash log files
crash.log
crash.*.log

# Exclude all .tfvars files, which are likely to contain sensitive data, such as
# password, private keys, and other secrets. These should not be part of version
# control as they are data points which are potentially sensitive and subject
# to change depending on the environment.
*.tfvars
*.tfvars.json
variable.tf

# Ignore override files as they are usually used to override resources locally and so
# are not checked in
override.tf
override.tf.json
*_override.tf
*_override.tf.json

# Ignore transient lock info files created by terraform apply
.terraform.tfstate.lock.info

# Include override files you do wish to add to version control using negated pattern
# !example_override.tf

# Include tfplan files to ignore the plan output of command: terraform plan -out=tfplan
# example: *tfplan*

# Ignore CLI configuration files
.terraformrc
terraform.rc

# Optional: ignore graph output files generated by `terraform graph`
# *.dot

# Optional: ignore plan files saved before destroying Terraform configuration
# Uncomment the line below if you want to ignore planout files.
# planout
```
Purpose of each section:
1. Local Terraform directories
```bash
.terraform/
```
* Contains provider plugins and modules downloaded locally.
* Should never be committed as they are environment-specific.
2. Terraform state files
```bash
*.tfstate
*.tfstate.*
.terraform.tfstate.lock.info
```
* State files contain actual infrastructure data, including sensitive information.
* Lock files prevent concurrent Terraform runs and are local artifacts.
3. Crash logs
```bash
crash.log
crash.*.log
```
* Generated when Terraform crashes.
* Useful locally for debugging but not for version control.
4. Variable files
```bash
*.tfvars
*.tfvars.json
variable.tf
```
* Often contain secrets such as passwords, API keys, or environment-specific data.
* Do not commit sensitive credentials.
5. Override files
```bash
override.tf
override.tf.json
*_override.tf
*_override.tf.json
```
* Used to override resources locally.
* Can be ignored unless you have an example override file:
```bash
!example_override.tf
```
6. Terraform CLI configuration
```bash
.terraformrc
terraform.rc
```
* User-specific CLI configs, should not be committed.
7. Optional files
```bash
# Graph output files
# *.dot

# Plan files
# *tfplan*
# planout
```
* Graphs and plan files are optional outputs.
* Can be ignored to keep the repo clean.
